## ADDED Requirements

### Requirement: 系统 SHALL 在目标站点中执行候选人自动处理流程
系统 SHALL 仅在当前页面域名匹配用户配置目标域名时启动候选人自动处理；若不匹配，系统 MUST 阻止执行并返回可读错误信息。

#### Scenario: 站点匹配时允许执行
- **WHEN** 用户点击执行且当前页面域名匹配配置值（默认 `www.zhipin.com`）
- **THEN** 系统开始候选人自动处理流程

#### Scenario: 站点不匹配时阻止执行
- **WHEN** 用户点击执行且当前页面域名不匹配配置值
- **THEN** 系统拒绝执行并提示用户当前页面不在允许站点

### Requirement: 系统 SHALL 支持候选人列表到详情的顺序读取
系统 SHALL 通过页面 I/O 集成层读取当前候选人列表，并按列表顺序进入候选人详情页面读取在线简历内容。

#### Scenario: 成功读取候选人列表并进入详情
- **WHEN** 用户在候选列表页触发自动处理
- **THEN** 系统读取候选人列表并依次打开每位候选人的详情以获取在线简历文本

#### Scenario: 某个候选人详情读取失败
- **WHEN** 系统在处理某位候选人时无法读取其在线简历
- **THEN** 系统记录该候选人为失败并继续后续候选人处理

### Requirement: 系统 SHALL 基于 prompt 与简历内容调用 LLM 做收藏决策
系统 SHALL 将用户输入 prompt 与候选人在线简历内容组合为请求上下文发送给 LLM API，并根据结构化返回结果决定是否执行收藏。

#### Scenario: LLM 判定值得收藏
- **WHEN** LLM 返回“值得收藏”决策
- **THEN** 系统在候选人详情页触发收藏动作并记录成功结果

#### Scenario: LLM 判定不收藏
- **WHEN** LLM 返回“不建议收藏”决策
- **THEN** 系统跳过收藏动作并记录判定理由

#### Scenario: LLM 调用失败
- **WHEN** LLM API 请求失败或响应不可解析
- **THEN** 系统将当前候选人标记为失败并继续处理下一位候选人

### Requirement: 系统 SHALL 在候选人处理之间执行随机等待
系统 SHALL 在每位候选人处理结束后等待随机时长 $t$，其中 $1 \le t \le 5$（秒），再继续下一位候选人。

#### Scenario: 候选人处理后触发随机等待
- **WHEN** 某位候选人的“读取-判定-收藏/跳过”流程结束
- **THEN** 系统等待 1 到 5 秒之间的随机时长后继续处理下一位候选人
