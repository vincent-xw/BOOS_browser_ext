## MODIFIED Requirements

### Requirement: 上下文管理与输出协议声明 SHALL 被实际接入
系统 SHALL 将上下文裁剪能力接入 harness 的消息构造流程，并 SHALL 在构造请求时读取并应用
prompt 注册表中声明的输出协议。声明但从未生效的配置项 MUST NOT 保留在公开接口中。

harness SHALL 支持按名选择提示词。仅取默认（首个注册）提示词的实现是不可接受的 ——
那会使第二个及之后注册的提示词及其输出协议永远不可达。

#### Scenario: 历史超限时被裁剪
- **WHEN** 会话历史长度超过配置上限且 harness 发起 LLM 调用
- **THEN** 发送给模型的消息序列已按上下文管理策略裁剪

#### Scenario: 输出协议被应用
- **WHEN** 某个 prompt 声明了输出协议
- **THEN** 该声明在构造请求时被实际应用，而不是被忽略

#### Scenario: 省略提示词名称时使用默认提示词
- **WHEN** 调用方未指定提示词名称
- **THEN** harness 使用首个注册的提示词

#### Scenario: 指定提示词名称时使用该提示词
- **WHEN** 调用方指定了一个已注册的提示词名称
- **THEN** harness 使用该提示词及其输出协议

#### Scenario: 非默认提示词的输出协议能够生效
- **WHEN** 调用方指定了一个带输出协议的非默认提示词，而模型输出不符合该协议
- **THEN** harness 抛出输出协议不符的稳定错误码

#### Scenario: 提示词未注册
- **WHEN** 调用方指定了一个未注册的提示词名称
- **THEN** harness 抛出提示词未找到的稳定错误码

#### Scenario: 工具结果回填沿用发起时的提示词
- **WHEN** 某次运行以特定提示词发起远端工具调用，随后结果被回填
- **THEN** 继续循环时仍使用该提示词，而不是回退到默认提示词

## ADDED Requirements

### Requirement: 上下文裁剪 MUST NOT 切断工具调用与其结果的配对
裁剪历史时，一条 assistant 消息与它发起的全部工具结果 MUST 被视为不可分割的单元。
裁剪 MUST 在单元边界处发生。

孤立的工具结果消息（其 `tool_call_id` 找不到对应调用）会被真实的 OpenAI 兼容端点以 400 拒绝；
带调用但无结果的 assistant 消息则会让模型看到一个永不完成的调用。

#### Scenario: 裁剪点落在配对中间时不产生孤立工具结果
- **WHEN** 窗口上限导致裁剪点落在 assistant 与其工具结果之间
- **THEN** 裁剪结果中不存在没有对应调用的工具结果消息

#### Scenario: 裁剪点落在配对中间时不留下无结果的调用
- **WHEN** 窗口上限导致某 assistant 的工具结果被裁掉
- **THEN** 该 assistant 消息一并被裁掉，不会单独留下

#### Scenario: 一次调用的多个并行工具结果同去同留
- **WHEN** 某 assistant 消息发起了多个并行调用，且窗口不足以容纳全部
- **THEN** 该 assistant 与其全部工具结果作为整体保留或整体丢弃

#### Scenario: 单个单元超过窗口上限
- **WHEN** 单个不可分割单元本身就超过窗口上限
- **THEN** 系统保持该单元完整并接受超出上限，因为截断的配对必然被端点拒绝

#### Scenario: 不带工具调用的消息可独立裁剪
- **WHEN** 历史中的 assistant 消息不含工具调用
- **THEN** 该消息可以被单独裁剪

### Requirement: 裁剪摘要 SHALL 作为系统消息发送给模型
发生裁剪时，系统 MUST 把裁剪摘要作为系统消息前置到发送给模型的消息序列中。
仅生成摘要而不发送是不可接受的 —— 模型会以为看到的就是完整历史。

#### Scenario: 发生裁剪时注入摘要
- **WHEN** 历史被裁剪后 harness 发起 LLM 调用
- **THEN** 消息序列首条为系统消息，内容说明有多少条历史被裁剪

#### Scenario: 未发生裁剪时不注入摘要
- **WHEN** 历史未超过窗口上限
- **THEN** 消息序列中不含裁剪摘要的系统消息

### Requirement: 挂起调用的持久化 SHALL 包含提示词名称
挂起调用存储 MUST 保存发起该调用时使用的提示词名称，使进程重启后的回填仍能沿用同一提示词。

#### Scenario: 提示词名称随挂起调用落库
- **WHEN** 以特定提示词发起的远端工具调用被持久化
- **THEN** 该提示词名称与会话标识、工具名一并保存

#### Scenario: 进程重启后回填沿用原提示词
- **WHEN** 承载 harness 的进程重启后收到此前发起的调用回填
- **THEN** 继续循环时使用原提示词，而不是默认提示词
